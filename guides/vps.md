# VPS 节点复用与新建指南

已有 VPS 先检查节点能否复用。确需新建时，首条路线采用 Xray／VLESS＋REALITY＋Vision，外层为 TCP。本文用于规划和逐步指导客户，实际安装、握手及出口结果待客户现场验证。开发机只做离线检查和合成模拟，现场步骤限客户本人已授权的 VPS 与设备。

```text
准备恢复 → 看现有节点
            ├─ 兼容且可独立发凭据 → 复用，跳过安装
            ├─ 资料不足或不兼容   → 保留原状，等客户决定
            └─ 确需新建且已授权   → 核对材料、端口、安装和监听
                                      ↓
           服务读回 → 电脑与所选手机各自验证握手和出口
                                      ↓
                再进入日常分流、重连和应用验收
```

## 需要购买 VPS 时先读

[VPS 节点选购与部署准备指南](vps-purchase.md)是本项目给客户的主要采购参考守则。没有兼容节点可复用、确需购买时，先按该指南筛选国家与套餐、比较运营商线路、核查 IP 质量，再由客户本人确认订单和付款。评测 IP 只用于候选筛选，开通后必须复核实际分配的 IP，并准备 SSH 与恢复控制台资料，再进入本页分支 B。

Agent 每次推进一项，配合指南对应图示；记录候选供应商、地区、套餐、费用及理由，采购决定由客户本人作出。不能把绿色解锁标记、住宅标签或 0% 评分当作 Claude 账号可用或没有历史报告的保证。

## IP 历史记录必须主动核查

选定候选后主动按 [IP 历史核查流程](ip-history.md)查询可取得的测试 IP，开通后重查实际分配 IP。发现明确滥用报告或污染记录时告知客户并换候选，不继续部署或切换该 IP。查询失败或资料缺失不能记为通过。API 可用时调用本地核查脚本，其他明确记录由 Agent 一并核对；不承诺证明“从未被滥用”。

## 先确认恢复和授权

客户先保留原接入，在本地打开[恢复指南](recovery.md)，填好恢复卡并验证原业务样本。若本轮涉及 VPS 变更，客户还要确认能通过独立于待切换连接的供应商控制台进入 VPS，并知道如何撤回本轮新增的配置和防火墙规则。保存可用的旧配置、原监听和防火墙状态，核对 SSH 管理入口的恢复办法。控制台不可用、原业务基线不明或回退方法缺失时，停在预检。

购买前确认实际使用地点和账号条件。确有新增费用时，客户先查看官方价格、计费方式、费用上限和释放时间，再确认采购。VPS 采购、安装、调整防火墙、分配设备身份和设备切换按各自获准的范围操作。[Claude 支持地点](https://support.claude.com/en/articles/8461763-where-can-i-access-claude) · [Claude 入门](https://support.claude.com/en/articles/8114491-get-started-with-claude) · [客户操作与反馈单](../docs/windows-iphone-field-test.md)

## 分支 A　复用现有节点

1. 让节点所有者在其控制台或服务端私下核对实际 Xray 版本、正在使用的监听端口、VLESS＋REALITY＋Vision／TCP，以及主机防火墙和云防火墙。已有正常联网的 VPS 还需证明这条具体节点符合要求。
2. 确认可以为 电脑和所选手机分配并分别撤销独立设备身份。若要修改现有服务，先确认变更范围和回退入口。复用继续使用原兼容版本和监听端口，保留现有业务与客户端配置。两端握手和出口尚无证据时，先记「候选复用」，走下方验收。
3. 资料缺失、协议不符、无法独立发放身份或测试失败时，停下并说明缺项。客户可以补证据，或决定是否另建节点。禁止把未查明的现有节点覆盖成新配置。

## 分支 B　在授权的新 VPS 上新建

1. 在客户新 VPS 上核对 Linux x64 或 ARM64、systemd、管理员权限和 SSH 管理入口。优先评估 TCP 443。确认端口空闲，并分别核对主机和云防火墙对该 TCP 端口的有效规则。若 443 已被占用或无法放行，在客户批准的候选中选合格端口。保留 SSH 和原业务规则，端口与权限不明时先停。
2. 从[固定清单](../scripts/xray/upstream.json)取得官方安装脚本和对应架构的 Xray v26.10.31 归档。客户可用 `sha256sum` 分别计算两个本地文件的摘要，与清单逐项比较。架构、来源或摘要不符时停止。清单记录归档与官方发行资源摘要的对照结果，独立发行签名待验。[固定版官方安装脚本](https://github.com/XTLS/Xray-install/blob/04e6f3bd9534811ed901a48c47b2c042dd64eb3a/install-release.sh) · [Xray 固定发行](https://github.com/XTLS/Xray-core/releases/tag/v26.10.31)
3. 客户在授权窗口内按固定官方脚本的 `install --local` 分支使用已核对的本地归档。脚本仍可能安装缺失依赖、写入系统文件和处理服务。若新实例已有需要保留的服务，或所需权限、依赖和影响超出授权，先停下来核对。安装后读回实际 Xray 版本及服务状态，再准备本轮监听。[固定版官方安装脚本](https://github.com/XTLS/Xray-install/blob/04e6f3bd9534811ed901a48c47b2c042dd64eb3a/install-release.sh)
4. 客户在 VPS 私下准备 REALITY 配置和两份独立设备身份，按 [节点材料指南](materials.md) 生成文件，或按 [Xray 配置说明](../scripts/xray/README.md) 手动核对字段。用该版本的配置检查入口通过校验后，按已授权范围启用本轮监听。读回实际监听地址在本机是否符合预期、实际 TCP 端口和两层防火墙结果。安装或语法检查失败时停在当前关，旧接入受影响时先按恢复卡复原。离线契约的合成样例只用于理解字段和验证流程。[Xray 固定版传输源码](https://github.com/XTLS/Xray-core/blob/v26.10.31/infra/conf/transport_security.go)

## 复用与新建共用的放行证据

| 分开记录 | 现场核对与停点 |
| --- | --- |
| 服务端读回 | Xray 实际版本、服务运行、实际 TCP 监听、主机及云防火墙、设备身份相互独立。证据不全时先补读回。 |
| Windows 互通 | 用 Windows 独立配置对指定节点验证 VLESS＋REALITY＋Vision 握手和该连接的出口。显式代理样本可用来隔离协议问题。进入日常使用前，仍按 [Windows 指南](windows.md)单独验 TUN 分流和真实应用路径。 |
| Mac 互通 | 按 [Mac 指南](mac.md) 用独立 Mac 节点核对 Karing 握手及出口，核对通过后再进入客户约定的 VPN 和规则。 |
| 手机互通 | 用所选手机的专属二维码和授权的临时测试窗口，验证指定节点的握手与出口。出现故障时回到原 VPN。之后按 [iPhone](iphone.md) 或 [Android](android.md) 指南单独验 Wi-Fi、蜂窝、重连和应用。 |

TCP 可达、协议握手和出口一致各有独立证据。握手失败先核对所测客户端版本、节点、服务名、Short ID、指纹和设备身份。mihomo 上游对 Xray v26.7.11 及以后版本有兼容性说明，v26.10.31 在两端的实际结果仍待确认。停在首个失败项，按[客户反馈单](../docs/windows-iphone-field-test.md#4-客户反馈模板)留下脱敏结论。更换版本或协议前，单独审查影响和安全更新。[mihomo REALITY 文档](https://wiki.metacubex.one/en/config/proxies/tls/#reality-opts) · [Xray 固定版传输源码](https://github.com/XTLS/Xray-core/blob/v26.10.31/infra/conf/transport_security.go)

## 只有聊天时怎么做

Agent 每次只给当前一项，说明客户在哪一端操作、预期看到什么、什么情况停止。可按进度选择一条提示发给客户。

- 「先试打开原业务样本和离线恢复卡。若本轮会改 VPS，也请验证能从供应商控制台进入。只告诉我是否可用。」
- 「这一步请在现有 VPS 核对监听、协议及能否给两台设备分别授权。回报通过、未知或缺哪项，原始配置留在 VPS。」
- 「请在已授权的新 VPS 核对候选端口是否空闲，并分别查看主机和云防火墙。只回报端口选择及两层结论。」
- 「先核对固定脚本和归档的两个摘要，只回报架构和各自是否一致。一项不符就停在这里。」
- 「如果安装窗口和影响都已确认，请按固定版的本地归档步骤操作。先只回报安装后读到的 Xray 版本和服务状态。」
- 「先只测当前这台设备。告诉我握手是否成功、出口是否符合预期，以及最后一个通过的步骤。另一台设备另记。」

有本地工具时，离线可核对版本清单、下载文件的摘要和合成配置形状。实际 VPS 权限、端口监听、握手及出口都由客户在现场核对。按 [README](../README.md#客户本地进度)记录客户已报告的结论。只有聊天时，用纸面或本地表保存交付标签、环境别名、时间和时区、结果及下一步。实际 IP、登录信息、SSH 和 REALITY 私钥、UUID、节点链接、二维码及原始日志留在客户环境。电脑配置和手机二维码按设备私下交付，规则另存。
