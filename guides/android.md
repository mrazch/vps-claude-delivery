# Android 手动接入与双网络验收

本文用于 Windows＋Android 分支，手机端选用 v2rayNG。首测候选为官方 2.3.15，发行说明列出 Xray-core v26.10.31。Android 版本、安装包、节点导入、实际握手和双网络由客户操作时逐项确认。实际操作只在客户已授权的设备和 VPS 上进行，开发环境只做离线验证。[v2rayNG 2.3.15 官方发行](https://github.com/2dust/v2rayNG/releases/tag/2.3.15)

```text
保存原连接和恢复卡 → 导入 Android 专属节点 → 用户批准 VPN
                                              ├─ 仅 Wi-Fi → 实际路径、出口
                                              └─ 仅蜂窝   → 实际路径、出口
                                                          ↓
                            重连复验 → 在约定设备测试 Claude 回复
                            任一步异常 → 按卡恢复原连接并留反馈
```

## 接入前

1. 把本页和[恢复指南](recovery.md)保存到离线也能打开的位置。先确认原业务样本能用，记录旧 VPN 应用、原节点和路由、Wi-Fi 与移动数据状态，以及系统是否启用了「始终开启 VPN」或「阻止不使用 VPN 的连接」。企业或学校设备的管理策略由管理员处理。[Android VPN 帮助](https://support.google.com/android/answer/9089766?hl=zh-Hans)
2. 从 [2dust 官方发行页](https://github.com/2dust/v2rayNG/releases/tag/2.3.15)按当前设备与交付版本选择安装材料。先核对 Android 版本、设备架构和发行文件。来源、文件或签名核对有异常时停止。上游提供 GPG 签名核对方法。安装与系统授权由客户自己操作。[官方签名说明](https://github.com/2dust/v2rayNG#gpg-verification--gpg-签名校验)品牌、系统版本和客户端发行渠道会影响菜单和可用功能。
3. 按[节点材料指南](materials.md)私下取得本台 Android 的二维码或单节点分享文本，确认服务端已授权对应独立身份。保留原 VPN 和旧配置。二维码、分享文本和节点链接按密码保管，可在另一块可信屏幕打开二维码，不要发往聊天、公共扫码网站或云剪贴板。

## 导入和连接

1. 在 v2rayNG 的新增配置入口选扫码，使用本机专属二维码。如无法扫码且当前版本提供剪贴板导入，可从本地受保护的文本复制单节点分享链接，在 App 中导入后清理该剪贴板条目及可见历史。导入为新条目，按本地交付记录核对节点别名、VLESS、TCP、REALITY 和 Vision 参数。解析错误或字段缺失时先停。[v2rayNG 2.3.15 导入入口源码](https://github.com/2dust/v2rayNG/blob/2.3.15/V2rayNG/app/src/main/res/values/strings.xml)
2. 在约定的切换窗口从原 VPN 应用暂停旧连接，选中刚导入的节点和约定的路由设置。若已启用按应用分流，确认目标 App 或浏览器未被排除。节点二维码用于导入连接参数，路由和按应用设置另行核对。
3. 从 v2rayNG 发起 VPN 连接。系统弹出连接请求时，核对应用是自己刚打开的 v2rayNG，再由客户亲自批准。可在 Android「设置」搜索 VPN，核对活动项为 v2rayNG。若旧 VPN 的始终开启策略或设备管理阻止切换，按恢复卡保留原连接，记录阻断原因。[Android VPN 授权机制](https://developer.android.com/develop/connectivity/vpn) · [Android VPN 帮助](https://support.google.com/android/answer/9089766?hl=zh-Hans)

## 两张网分别验收

| 测试 | 操作与所需结果 |
| --- | --- |
| 仅 Wi-Fi | 在设置里关闭移动数据并连上约定 Wi-Fi。确认系统活动 VPN、所选节点和约定路由设置。用普通 App 或浏览器发起新请求，核对实际应用路径，再用约定的出口样本核对出口一致。 |
| 仅蜂窝 | 从设置关闭 Wi-Fi，打开移动数据，确认套餐允许测试。重新核对活动 VPN、应用路径及出口。Wi-Fi 的结果单独保留。 |
| 断开重连 | 在约定的网络主动断开后重新连接，再验节点、应用路径和出口。如果约定要验证 Wi-Fi 切到蜂窝后自动恢复，另做一轮并先观察是否自动重连。手动和自动结果分别记录。 |
| Claude 实际回复 | 在约定的设备上由客户本人使用官方 App 或网页，满足使用条件后发送一条无个人信息的测试消息，看到新回复才记通过。记录实际设备、入口和网络。如果约定两张网都验 Claude，各发一条新消息。 |

应用路径用当前版本能提供的本地连接或核心日志核对，按时间将测试动作、目标和实际出站对应起来，必要时在获准的 VPS 上核对同一时段证据。如果只能看见 VPN 图标、延迟或出口检查结果，路径单独记「未证实」。约定直连时另外验证普通应用直连样本。检查结束恢复 Wi-Fi 和移动数据到约定状态。[Android 网络设置](https://support.google.com/android/answer/9654714?hl=en)

## 失败时恢复和反馈

1. 从 v2rayNG 断开本次连接。App 打不开时，在系统 VPN 设置确认活动项后尝试断开。若本轮启用了始终开启或阻断设置，按恢复卡撤销本轮变更。[Android VPN 帮助](https://support.google.com/android/answer/9089766?hl=zh-Hans)
2. 将 Wi-Fi、移动数据、原 VPN 应用、节点和原有自动连接策略恢复到基线，然后用原业务样本复验。若无法断开或恢复，停在最后一个可确认状态，使用事先准备的本地支持入口。保留其他 VPN 配置和系统管理设置，避免执行通用网络重置。[离线恢复指南](recovery.md)
3. 本地记录交付版本、设备别名、Android 和 v2rayNG 版本、Wi-Fi 或蜂窝、测试时间与时区、最后通过项、失败阶段和原业务复验结果。按[反馈模板](../docs/windows-iphone-field-test.md#4-客户反馈模板)交接摘要，原始日志、节点材料、实际 IP 和账户信息留在设备或 VPS。仅用聊天时也可以照这些字段手写。
