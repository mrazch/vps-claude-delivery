# 自动核查 IP 历史记录

客户选定 VPS 候选后，Agent 主动核查能取得的测试 IP；商家未提供测试 IP 时，明确记录购买前尚不能核查该实例。开通后必须对实际分配的 IP 重新查询，不能拿商家的样例结果替代。现有节点复用、更换 IP 后同样重查。开发机不执行真实 IP 查询。

## 判断与提醒

- **发现记录**：AbuseIPDB 的报告数大于 0、风险评分大于 0、存在最后报告时间，或其他可靠来源有明确的滥用／污染记录，均告知客户并暂停部署或切换到该 IP，建议申请换 IP、换实例或其他候选。不得用“现在评分为 0”掩盖已知报告。不自动付费、更换或删除实例。
- **查询范围内无记录**：评分为 0、报告数为 0、最后报告时间为空，且其他已查来源没有明确污染记录，才可记录本项检查完成。只能表述为“本次来源与范围内未发现记录”。
- **无法核查**：缺密钥、验证码、服务不可用、限流、字段缺失或 IP 不匹配，记未知，不得当作通过。Agent 有浏览器时可查询官方网页补证；只有聊天能力时请客户在官网查询并保存脱敏结论。不得为自动化付费开通套餐。

滥用报告是数据库收录的投诉或风险信号，不等于对当前客户违规的认定。客户要求排除明确历史记录，本流程因此采取换 IP 的处理。任何数据库都不能证明一个 IP 从未被滥用。

## 在客户设备自动查询

客户已有 Python 3.9 或更高版本、同意把拟查 IP 发送到 AbuseIPDB 后，Agent 使用本地脚本。API 密钥由客户本人从官方账号取得，留在客户设备，不能发送到聊天。

1. 在交付目录建立 `runtime/ip-history/`，由客户私下保存 `input.json`：

~~~json
{
  "ip": "<本次要核查的实际公网 IP>",
  "apiKey": "<客户自己的 AbuseIPDB API 密钥>",
  "purpose": "assigned"
}
~~~

`purpose` 在购买前测试填 `candidate`，开通后的实际 IP 填 `assigned`，已有节点填 `existing`。IP 填字面地址，不填域名。目录应仅客户本人可访问。

2. Agent 在客户设备运行以下命令，不等待客户再提出“查历史”：

~~~powershell
python scripts/check-ip-history.py --check
~~~

Mac 使用 `python3`。省略 `--check` 只显示说明，不联网。脚本只读查询 AbuseIPDB，固定查最近 365 天，密钥通过 HTTPS 请求头发送，拒绝跳转，不向数据库提交举报或修改节点。API 不支持无限历史查询，响应中的最后报告时间即使早于当前窗口也会触发提醒。[官方接口与范围说明](https://docs.abuseipdb.com/#check-endpoint)

3. 读取本次返回状态，告知客户结论；原始 IP 和独立查询回执保存在本地 `runtime/ip-history/`，屏幕不输出 IP 或 API 密钥。`flagged` 和 `unknown` 返回非零退出码。脚本只覆盖 AbuseIPDB，Agent 仍需对采购评测中出现的其他明确污染／封禁记录核对来源和时间，不能把“绿色解锁”当作无滥用历史。不要向客户宣称脚本覆盖全部数据库。

4. 将来源、查询时间、范围、评分、报告数、最后报告时间、是否存在其他明确记录和下一步写入本地反馈表。再次查询生成独立回执；本机同一 IP 的旧风险记录不会被新的零评分清除。确认回执属于当前实际 IP 与本次采购，不能复用旧节点或样例 IP 的结果。

提示客户时可以说：“查到该 IP 有历史滥用报告／污染记录，来源为……，查询时间和范围为……。按本项目选购要求，这个 IP 不继续采用，建议申请更换。”查询失败则明确说“尚未完成核查”，而不是“IP 干净”。
