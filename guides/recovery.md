# 断网后手动恢复与换 Agent 续接

本手册用于恢复切换前已知可用的连接。切换前把本手册和 对应的 [Windows](windows.md) 或 [Mac](mac.md) 手册，以及对应的 [iPhone 手册](iphone.md)或 [Android 手册](android.md)保存到设备本地，再断网试打开一遍。可以另留一份纸质恢复卡。恢复步骤通过本机原生界面完成，Agent 离线时也能照做。网络若在运营商、路由器或旧服务端一侧故障，恢复设置后仍需排查。

```text
新路线断网或 Agent 掉线
        ↓
打开本地恢复卡 → 关闭本次接管 → 恢复原设置与原连接
                                       ↓
                               验证原业务样本
                               ├─ 通过 → 留本地回执，等待续接
                               └─ 失败 → 停在已知状态，记录卡点
```

## 切换前填写恢复卡

每台设备单独保存一份。先验证当前可用，再记录当时状态。原配置、凭据和安装材料留在本机受保护的位置。恢复卡中的具体路径和设置细节仅供本人离线使用，另做一份可交接的摘要。

| 填写项 | 要记录的内容 |
| --- | --- |
| 设备和验证 | 本地设备别名、系统与客户端版本、基线验证时间、一个能验证原业务的普通样本。 |
| Windows 基线 | 原客户端、配置和节点的本地别名，运行方式、系统代理、TUN、原连接是否开机恢复，以及本次预计改变的其他项目。记录怎么在原生界面打开和恢复。 |
| Mac 基线 | 原 VPN、原节点、VPN 按需连接状态、使用中的网络服务和系统代理。记录原业务样本与恢复入口。 |
| iPhone 基线 | 原 VPN 客户端、配置和节点的本地别名，连接和按需连接状态，Wi-Fi 与蜂窝数据原状态。记录怎么打开原客户端。 |
| Android 基线 | 原 VPN 应用、配置与节点，Wi-Fi、移动数据、始终开启 VPN、阻止不使用 VPN 的连接及按应用分流设置。记录原应用的恢复入口。 |
| 本地材料 | 已保存的手册、旧配置或备份、必要且已核验的原安装材料。确认本人能在离线时打开。把新客户端界面不可用时该用哪个本地入口、怎么打开，也写进纸质恢复卡。 |
| 立即回退条件 | 例如预期直连或 VPS 样本失败、日常应用异常、重启无法恢复，或超过约定切换时间。 |

切换前逐项确认旧节点和配置仍可用，保留旧服务、账户和接入凭据。服务端变更若可能同时影响旧路线，应先准备独立恢复路径。只要恢复仍依赖同一条待切换网络、在线聊天或云盘，先补齐本地入口再切换。

## Windows 恢复

1. 打开本地恢复卡，停止切换和重试。若 Clash Verge Rev 界面可用，在界面关闭本次启用的 TUN 和系统代理，再退出本次新客户端。若本次开启了自启或 TUN 自动恢复，在界面恢复其原状态，避免下次登录再次接管。
2. 在 Windows「设置」的代理页面核对实际状态，按恢复卡还原原代理设置。若客户端无法打开、系统状态与客户端开关不一致，优先使用本机事先留好的恢复入口。对自己未改动的网卡、防火墙、DNS 和系统服务保持原设置。[Clash Verge Rev Windows 故障说明](https://www.clashverge.dev/faq/windows.html)
3. 打开原客户端，选回原配置、节点和模式，恢复切换前的连接状态。基线为无 VPN 时，保持原本的联网方式。先验证恢复卡里的原业务样本，再核对原来的应用或分流结果。需要重启验证时，等普通联网恢复并保存本地进度后再做。
4. 如无法关闭新接管、无法选回原状态或原业务仍失败，记录最后可确认的设置和故障现象，停在当前可解释的状态。按事先准备的本地支持入口处理，避免反复叠加代理或执行通用网络重置。

## Mac 恢复

先从 Karing 断开本次连接。若 App 不可用，到 macOS 系统设置的 VPN 页面确认活动项后处理。按恢复卡恢复本轮修改的按需连接和代理选项，再回到原 VPN 和原节点，用原业务样本复验。详细步骤见 [Mac 恢复](mac.md#mac-恢复)。

## iPhone 恢复

1. 从 Shadowrocket 断开本次连接。若 App 界面不可用，在 iOS「设置」中搜索 VPN，确认名称后尝试断开本次连接。若 VPN 立即自动重连，检查本次新增的按需连接设置，并按恢复卡撤销本次变更。在系统 VPN 设置中确认活动项，再继续。保留系统管理描述文件和其他 VPN 配置。[Apple VPN 故障说明](https://support.apple.com/en-gb/102281)
2. 将 Wi-Fi 和蜂窝数据按恢复卡恢复。打开原 VPN 客户端，选回原配置和节点，恢复原连接及按需连接状态。基线未连接 VPN 时，恢复原本的联网方式。[Apple 蜂窝数据设置](https://support.apple.com/guide/iphone/view-or-change-cellular-data-settings-iph3dd5f213/ios)
3. 在原网络上用日常 App 或浏览器验证恢复卡里的原业务样本。若日常依赖两种网络，分开复验。系统显示 VPN 图标时也要确认活动项及业务结果。旧配置找不到或被管理策略锁定时，记下当前状态并走本地支持入口。

## Android 恢复

1. 从 v2rayNG 断开本次连接。应用无法打开时，从 Android 设置进入 VPN，确认活动项后再操作。本轮若变更了始终开启或阻止非 VPN 连接，按恢复卡还原本轮变更。[Android VPN 帮助](https://support.google.com/android/answer/9089766?hl=zh-Hans)
2. 恢复原 Wi-Fi、移动数据、VPN 应用、节点和原自动连接策略。用原业务样本复验。设备管理阻止恢复时，记录最后可确认的状态，走恢复卡上已有的本地支持入口。

## 换 Agent 时怎么交接

Windows 分支有本地进度文件时，让新 Agent 在同一个版本文件夹运行 `node scripts/progress.cjs --customer status`。手动恢复并确认原业务可用后，才用 `restore` 记录恢复。随后重新验证中断阶段。命令见 [客户本地进度](../README.md#客户本地进度)。

本地也可以写一份可转交摘要。每台设备各写一行或一个小段，用设备别名、阶段、时间及时区、实际操作、看到的结果、当前状态和下一步说明。分开标注「离线模拟」「已有个人实测」「客户实际操作结果」。尚未执行、失败、已回到原连接分别记。若回退尚未验证，写「已尝试恢复，原业务待验证」。

可转交摘要只记例如「样本 A 直连」「出口与预期一致」「Wi-Fi 已收到 Claude 回复，蜂窝未测」。私钥、密码、验证码、账户标识、UUID、二维码、访问链接、实际 IP、未清理截图、原始日志和真实配置留在设备或 VPS。新 Agent 可从[项目说明](../README.md)核对版本和阶段，使用本地脱敏摘要或手写清单定位第一个缺少证据的步骤。执行前先核对当前状态和本轮授权，已确认的步骤按其证据范围沿用。
